# V5 测试方案

---

## 一、测试分层

| 层级 | 范围 | 工具 |
|------|------|------|
| 单元测试 | 各模块内部逻辑 | pytest + mock |
| 集成测试 | 新节点 + DAG + 渲染管线 | pytest + 真实依赖 |
| 数据质量测试 | 趋势采集、数据归因准确性 | 人工标注 + 自动对比 |
| 音频质量测试 | 声音克隆/配乐/音效 | MOS 评分 + 自动化指标 |
| 安全合规测试 | 声音克隆授权、数据隐私 | 渗透测试 + 流程审计 |
| 性能基准 | 延迟/吞吐/GPU 资源 | pytest-benchmark + GPU 监控 |
| 端到端 | 全自主创作流程 | 自动化脚本 + 人工验收 |

## 九、对研发方案的风险补充

### 1. 趋势 API 的灰色地带

抖音、小红书没有官方开放的热搜 API，爬虫采集存在法律和封号风险。**建议：** V5.0 先支持手动导入 + RSS 源 + 有官方 API 的平台（微博、B站、YouTube），抖音/小红书标记"实验性"并做好降级。

### 2. 声音克隆的滥用风险

即使有授权流程，仍可能被用于深度伪造。**建议：** 除了授权书 OCR，增加"训练时录一段指定文案用于验证是同一人"的活体确认环节。输出音频的水印必须覆盖压缩/剪辑后仍可检测的场景测试。

### 3. AI 配乐的版权确定性

Stable Audio 的训练数据是否侵权尚有争议，生成音频的版权归属不明确。**建议：** 商用场景默认使用 MusicGen（MIT 许可，训练数据为 Shutterstock 授权音乐），Stable Audio 标记"非商用/实验性"。需在 UI 上明确标注版权状态。

### 4. 数据归因的因果 vs 相关

特征归因只能发现相关性，不能证明因果。"前 3 秒悬念 → 高完播"可能只是因为该账号粉丝偏好这类内容。**建议：** 归因结果用"相关性"而非"因果"描述，置信度 < 0.7 时附带"建议通过 A/B 测试验证"的提示。

### 5. CriticAgent 的标准校准

Critic 的质检标准如果偏严会增加人工介入成本，偏松则形同虚设。**建议：** 初期默认宽松模式，收集用户对 Critic 判断的同意/否决数据，逐步校准阈值。提供"这个建议有用吗？"的反馈按钮。

### 6. 跨项目模式的过拟合

如果高表现视频恰好因为非剪辑因素（如蹭了某个热点话题），提取的模式可能无法迁移。**建议：** 模式评分需排除话题红利——对比同期同账号其他视频，仅保留在排除话题因素后仍然表现优异的模式。

### 7. 自主推进的"失控"风险

全自动推进到最终渲染，如果中间某步骤产出低质量结果会浪费大量算力。**建议：** 每个自动步骤的输出做轻量质检（非 CriticAgent 的全量评估，而是快速 sanity check），低于阈值时自动暂停并通知用户。

### 8. 音频模型的 GPU 资源竞争

声音克隆、配乐生成、音效合成都需要 GPU。如果与视频生成（VACE/Open-Sora）并发，12GB 显存大概率不够。**建议：** 实现 GPU 任务队列，音频和视频生成互斥调度。性能基准测试需覆盖"音频生成 + 视频渲染同时进行"的场景。
