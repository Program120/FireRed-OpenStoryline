# V1 产品经理方案

> V1 定位：从"一次性生成"升级为"可迭代编辑"的 AI 视频工作流

---

## 一、核心判断

V1 的核心命题是：**把"能跑通的 Demo"变成"能日常用的工具"**。

| 痛点 | 用户价值 | 技术难度 | V1 优先级 |
|------|---------|---------|---------|
| 局部修改/增量编辑 | ★★★★★ | ★★★☆☆ | **P0** |
| 风格模板/会话持久化 | ★★★★☆ | ★★☆☆☆ | **P0** |
| 可视化预览与交互 | ★★★★☆ | ★★★★☆ | **P1** |
| 渲染质量提升 | ★★★☆☆ | ★★★☆☆ | **P1** |
| 多平台比例适配 | ★★★☆☆ | ★★☆☆☆ | **P2（V2）** |

## 二、P0-1：增量编辑能力

**问题根因：** V0 是单 Agent 顺序执行 10 步 pipeline，没有中间状态持久化。

**方案：引入 Project State + DAG 任务图**

1. **Project State 持久化**：每步 pipeline 输出持久化为 Project JSON，每次对话基于已有状态做增量修改
2. **DAG 依赖图替代线性 Pipeline**：用户修改某步时只重跑下游受影响节点
   - 调整片段顺序 → 只重跑 PlanTimeline + RenderVideo（2步）
   - 更换配音 → 只重跑 Voiceover + PlanTimeline + RenderVideo（3步）
3. **Planner-Worker 多 Agent 架构**：
   - Planner Agent：理解用户指令，判断需修改哪些节点，生成最小执行计划
   - Worker Agents：可并行执行无依赖关系的任务

**技术选型：** 迁移到 LangGraph StateGraph，天然支持有状态 DAG 执行。

## 三、P0-2：风格模板与会话持久化

1. **User Profile 存储**：常用 intro/outro 模板、字幕偏好、BGM 风格标签、节奏偏好
2. **风格学习机制**：Agent 自动提取用户偏好，写入 Profile
3. **Session 持久化**：对话历史 + Project State 绑定存储，关闭浏览器再打开项目还在

## 四、P1-1：轻量可视化预览

**克制原则：V1 不做完整时间线编辑器，做"可视化的对话辅助"。**

1. **结构化时间线概览**：缩略图 + 时长 + 配音文本，用户可指着说"第3段换一下"
2. **低分辨率快速预览**：480p 快速预览，确认后再高质量渲染
3. **片段级指令解析**：Planner 理解"第X段"、"从X分X秒"等定位指令

## 五、P1-2：渲染质量基础提升

1. **FFmpeg 替代 MoviePy 核心渲染**：解锁硬件加速、转场效果、高级字幕、精确混音
2. **动态音频混合**：配音段自动压低 BGM（ducking）
3. **字幕样式模板**：预设 5-8 种常见样式

## 六、V1 不做的事情（V2+ Backlog）

| 功能 | 推迟原因 |
|------|---------|
| 多平台比例自动适配 | 涉及智能构图裁切，需额外视觉模型 |
| 完整可视化时间线编辑器 | 前端工程量巨大，偏离核心定位 |
| 多模型 Provider 支持 | 短期够用 |
| 跨片段语义关联理解 | 需更复杂的视频理解方案 |
| 团队协作 | 用户量不够大 |

## 七、成功指标

1. 增量编辑命中率 ≥ 90%
2. 修改轮次从平均 5 轮降到 2 轮
3. 端到端时间控制在 15 分钟内（V0 约 30-40 分钟）
4. 周活跃创作者 7 日留存 > 40%

## 八、里程碑

| 阶段 | 时间 | 交付 |
|------|------|------|
| M1 | 第 1-3 周 | ProjectState + DAG + LangGraph 迁移 |
| M2 | 第 4-6 周 | Planner-Worker 多 Agent + 增量编辑跑通 |
| M3 | 第 7-8 周 | UserProfile + 风格模板 + Session 持久化 |
| M4 | 第 9-10 周 | FFmpeg 渲染 + 动态混音 + 字幕模板 |
| M5 | 第 11-12 周 | 低分辨率预览 + 片段指令 + 集成测试 |
