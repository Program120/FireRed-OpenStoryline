# V4 产品经理方案

> V4 定位：从"个人创作工具"升级为"团队级 AI 视频生产平台"，同时接入生成式视频模型打开新内容形态

---

## V3 复盘关键洞察

V1-V3 完成了单人创作闭环：从素材到成片可以全程在 OpenStoryline 内完成。但用户增长数据显示：**个人创作者付费意愿有限（ARPU < ¥50/月），而 MCN/企业团队（10-50 人）的采购预算是个人的 20-50 倍，且续约率更高。** 同时，VACE、Open-Sora 2.0、HunyuanVideo 等开源视频生成模型已达到可用水平，可以解决长期存在的"B-roll 素材不足"痛点。

V4 核心命题：**用团队协作撬动 MCN 商业化，用 AI 视频生成建立技术壁垒。**

## 二、P0-1：团队协作与多人项目管理

**核心判断：MCN 不会为"30 个人各用各的单人工具"买单。团队协作是 B2B 商业化的入场券。**

### 角色权限体系

| 角色 | 权限 |
|------|------|
| 机构管理员 | 全局设置、成员管理、品牌资产库管理、数据看板 |
| 编导 | 创建项目、编写指令、分配剪辑师 |
| 剪辑师 | 编辑项目、渲染输出、提交审核 |
| 达人/审核人 | 预览成片、添加标注评论、审批通过/打回 |
| 只读观察者 | 仅查看项目和数据 |

### 协作工作流

```
编导创建项目 → 分配剪辑师 → 剪辑师编辑 → 提交审核 → 达人/编导审片评论 → 修改 → 审批通过 → 发布
```

- 项目级评论系统：可针对时间线上的具体时间点添加标注（类似 Frame.io）
- 操作日志：谁在什么时间做了什么修改，完整可追溯
- 通知系统：项目状态变更自动推送（WebSocket + 邮件/飞书/企微 webhook）

### 不做实时协同编辑

V4 不做 Google Docs 式的多光标实时协同——技术复杂度极高且 MCN 的实际工作流是**接力式**（编导 → 剪辑 → 审核）而非同时编辑。项目锁机制（同一时间只有一人可编辑）足够。

### 存储架构升级

SQLite → PostgreSQL，支持多用户并发。项目数据、用户权限、操作日志、评论全部持久化。

## 三、P0-2：AI 视频生成集成

**核心判断：视频生成模型已从"实验室玩具"变为"可用工具"，OpenStoryline 拥有天然集成优势——我们有完整的脚本、时间线和素材语义上下文，可以精准指导视频生成。**

### 统一生成接口（VideoGen Provider）

与 V3 的多模型 Provider 抽象思路一致，V4 对视频生成模型做统一抽象：

| 模型 | 定位 | 适用场景 |
|------|------|---------|
| VACE (Alibaba) | 可控视频编辑与生成 | 参考图驱动的 B-roll、风格迁移、视频扩展 |
| Open-Sora 2.0 | 高质量文生视频 | 纯文字描述生成氛围空镜 |
| HunyuanVideo | 腾讯开源生成模型 | 中文场景优化 |
| 本地 ComfyUI | 自定义 pipeline | 高级用户自定义工作流 |

### 集成方式

1. **脚本驱动生成**：Planner 分析脚本，识别缺少素材的段落，自动建议生成 B-roll
2. **素材风格对齐**：用实拍素材的色调、光线作为 reference image 引导生成，保证视觉一致性
3. **时间线内嵌**：生成的片段直接插入时间线对应位置，无需手动导入
4. **人工审核门控**：AI 生成的片段默认标记为"待确认"，用户确认后才参与最终渲染

### 资源管理

视频生成对 GPU 要求极高。方案：
- 本地模式：用户自有 GPU（需 24GB+ VRAM），通过 ComfyUI 或本地推理
- 云端模式：接入阿里云 / RunPod 等 GPU 云服务，按使用量计费
- 混合模式：小任务本地、大任务云端

## 四、P0-3：内容合规与品牌安全检查

**核心判断：MCN 机构的合规风险是真金白银的损失（违约金、封号），自动化合规检查是 B2B 采购的硬性要求。**

### 检查能力

| 检查项 | 实现方式 | 优先级 |
|--------|---------|--------|
| 竞品 logo/品牌检测 | YOLO 物体检测 + 品牌 logo 数据库 | P0 |
| 敏感词/违禁用语检测 | 字幕文本 + ASR 文本扫描 | P0 |
| 产品展示时长合规 | 素材知识图谱标签 + 时间线统计 | P0 |
| 肖像权/未授权人脸 | 人脸检测 + 授权人脸库比对 | P1 |
| 平台规则适配 | 各平台内容政策规则引擎（抖音/小红书/B站） | P1 |

### 工作流集成

```
渲染完成 → 自动合规扫描 → 生成合规报告（通过/警告/拒绝）→ 人工复核警告项 → 确认发布
```

品牌方可以预设合规规则模板（"品牌安全策略"），绑定到该品牌的所有项目。

## 五、P1-1：API / SDK

**核心判断：API 是 MCN 技术团队的刚需，也是平台化的基础。**

### RESTful API v1

```
POST   /api/v1/projects                    # 创建项目
POST   /api/v1/projects/{id}/materials      # 上传素材
POST   /api/v1/projects/{id}/instructions   # 发送编辑指令
GET    /api/v1/projects/{id}/status         # 查询项目状态
GET    /api/v1/projects/{id}/render         # 获取渲染结果
POST   /api/v1/projects/{id}/render         # 触发渲染
GET    /api/v1/projects/{id}/timeline       # 获取时间线
POST   /api/v1/projects/{id}/compliance     # 触发合规检查
```

### Python SDK

```python
from openstoryline import Client

client = Client(api_key="os_xxx", base_url="http://localhost:8000")
project = client.create_project(name="日报 2026-04-01")
project.upload_materials(["footage_01.mp4", "footage_02.mp4"])
project.instruct("用轻快的节奏剪辑一条 60 秒产品展示视频")
project.wait_for_completion()
project.download_render("output.mp4")
```

### Webhook 回调

支持 render_completed、compliance_checked、review_approved 等事件的 webhook 通知。

## 六、P1-2：数据分析与 A/B 测试

### A/B 测试工作流

1. 从同一项目创建 A/B 变体（不同封面、不同开头、不同标题）
2. 一键发布到平台（需授权绑定账号）
3. 回收平台数据（播放量、完播率、互动率）
4. 自动分析并推荐最优版本
5. 将分析结论沉淀为团队知识（"这类选题用疑问句标题 CTR 高 23%"）

### 内容数据看板

- 团队级视图：所有账号的发布数据汇总
- 剪辑策略归因：哪些剪辑模板/节奏/转场与高完播率相关
- 素材复用分析：哪些素材被多次使用，哪些从未使用

### 数据源

初期通过平台 API（抖音开放平台、B站 API）或用户手动录入；后期考虑浏览器插件自动采集。

## 七、P1-3：视频项目版本控制

### 设计原则

- 每次编辑指令自动创建一个版本快照（自动保存，用户无感）
- 版本列表展示：时间 + 操作摘要 + 缩略图
- 一键回退到任意历史版本
- 支持版本间 diff（时间线结构对比 + 参数差异高亮）
- 分支能力（V4.1 考虑）：从某个历史版本 fork 出新分支

### 存储策略

增量快照（只存变更的 node artifact），不全量复制，控制存储开销。

## 八、P2-1：自动封面 / 缩略图生成

1. 从视频关键帧中自动提取候选封面（基于画面质量评分 + 人脸检测 + 构图评分）
2. AI 文字排版：自动在封面上叠加标题文字，适配平台尺寸
3. 风格与达人品牌一致（使用品牌素材库中的字体、配色）
4. 每次生成 3-5 个方案供选择

---

## 九、P2-2：插件 / 扩展生态

### 插件架构

- 定义标准插件接口（Hook 点）：`on_before_render`、`on_after_render`、`on_compliance_check`、`on_timeline_modified` 等
- 插件使用 Python 编写，通过 pip 安装或本地目录加载
- 内置插件市场（V4.1+）

### 首批示例插件

- 水印/二维码贴片插件
- 自定义合规规则插件
- 社交平台自动发布插件（抖音/B站/小红书）
- 字幕翻译插件（多语言字幕）

## 十、V4 不做的事情（V5+ Backlog）

| 功能 | 推迟原因 |
|------|---------|
| 实时多人协同编辑 | 技术复杂度极高，接力式协作已够用 |
| 自研视频生成模型 | 开源模型足够好，聚焦集成而非训练 |
| 全平台自动发布 | 各平台 API 限制多且不稳定，初期做手动 + 半自动 |
| 移动端 App | 先做好 Web 端，移动端不是 MCN 的核心场景 |
| 直播剪辑 | 需要实时流处理能力，与当前架构差异大 |
