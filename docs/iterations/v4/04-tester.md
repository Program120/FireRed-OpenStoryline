## 十二、对研发方案的风险补充

1. **PostgreSQL 迁移回归范围被低估** — SQLite → PostgreSQL 不只是换 driver，还涉及事务隔离级别差异、JSON 字段查询语法差异、并发锁行为差异。建议保留 SQLite 兼容模式并维护双模式 CI 测试。

2. **VideoGen Provider 的模型兼容性测试缺少标准** — VACE、Open-Sora、HunyuanVideo 各自的输入格式、分辨率限制、生成质量差异很大。建议建立统一的生成质量评测集（50+ prompt + 人工评分基线），每次模型升级后跑回归。

3. **合规检测的法律风险** — 合规引擎给出"通过"结果后，如果实际仍有违规，MCN 可能追责。建议合规报告明确标注"AI 辅助检测，不构成法律意见"，且 severity=block 的阈值宁严勿松。

4. **A/B 测试的统计显著性** — PM 方案未明确样本量要求和显著性检验方法。建议使用贝叶斯 A/B 测试而非频率派 t 检验，更适合小样本（单条视频几千到几万播放量）。

5. **插件沙箱在 macOS 上的实现限制** — seccomp 是 Linux 专属，macOS 需用 sandbox-exec 或纯 Python 层面限制。建议明确支持平台，或统一使用 Docker 容器作为沙箱。

6. **编辑锁的 Redis 单点故障** — 当前方案 Redis 是单点。如果 Redis 宕机，所有项目都无法获取编辑锁。建议支持无 Redis 的 PostgreSQL Advisory Lock 降级方案。

7. **180 人天的估算偏乐观** — P0-1（团队协作）涉及大量前端工作（权限管理 UI、评论组件、审核工作流 UI、通知设置），研发方案中未计入前端工时。实际应加 30-40 人天前端工作量。

8. **视频生成结果的版权风险** — AI 生成内容的版权归属尚不明确，MCN 商用场景下可能有法律纠纷。建议在生成素材的 metadata 中标注"AI 生成"，并提醒用户自行评估商用风险。
